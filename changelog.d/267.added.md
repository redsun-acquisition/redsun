`redsun.compute` runs a component's calls in worker processes. A component asks for a `ProcessExecutor` in its constructor or its `setup` and gets a `ProcessPool` of its own, which holds a `concurrent.futures.ProcessPoolExecutor` started with `spawn`. When a worker dies, the component's unfinished calls fail with `WorkerCrashed` and the pool starts new workers. The module also exports `ProcessPoolSettings` and `Priority`, and `OwnerUsage` gains `crashed`. The `compute` section of a session file gains `processes`, the number of workers of each pool, and `priority`, the priority of the workers (`low`, `normal` or `high`); a presenter's or view's entry gains `workers`, the number of workers of its own pool. The `inline_processes` fixture of `redsun.testing` runs each call in the test's thread after a pickle round trip.

```python
class MyController:
    def __init__(self, name: str, executor: ProcessExecutor) -> None:
        self._executor = executor

    def process(self, frames: list[np.ndarray]) -> None:
        self._executor.submit(fit, frames).then(self.sig_fit.emit)
```
