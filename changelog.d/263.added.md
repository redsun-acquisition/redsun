`redsun.compute` runs a component's calls on threads the session shares between its components. A component asks for a `ThreadExecutor` in its constructor or its `setup`, and `submit` returns a `Future` whose `then` hands the result to the main thread of a Qt session. The module also exports `ThreadPool`, `ThreadPoolSettings`, `BrokenPool`, `OwnerUsage`, `Limits`, `Preset` and `ComputeSettings`. `Session.compute` and the `compute` section of a session file choose how the cores are split, `Session.pool_settings` reports the result, `Frontend.results_thread` names the thread results are handed to, and the `inline_threads` fixture of `redsun.testing` runs each call in the test's thread. `redsun.injection.Registry` gains `register_resource`, which registers a value made on its first request, and `close`, which tears down the values made. `redsun` now depends on `threadpoolctl`.

```python
class MyController:
    def __init__(self, name: str, executor: ThreadExecutor) -> None:
        self._executor = executor

    def process(self, frames: list[np.ndarray]) -> None:
        self._executor.submit(median_of, frames).then(self.sig_median.emit)
```
